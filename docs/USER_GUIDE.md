## 1. 이 프로그램이 하는 일

드론이나 카메라로 촬영한 콘크리트 구조물 사진에서 **AI가 균열을 찾아내고**,
3D 모델 위에 정확히 얹어 **실제 크기(mm)의 폭과 길이**를 계산합니다.
결과는 `.twin` 파일 하나로 저장되며, 3D 화면에서 직접 확인할 수 있습니다.

```
사진 여러 장 + 3D 모델  →  [분석]  →  보고서(.twin)  →  [3D 뷰어로 점검]
                                              └→ PDF 보고서
                                              └→ 이전 검사와 비교
```

한 번 만든 `.twin` 파일에는 3D 모델·사진·검출 결과가 **모두 들어 있어**,
그 파일 하나만 있으면 다른 PC에서도 그대로 열어볼 수 있습니다.

## 2. 설치

### 2-1. 필요한 것

- **Windows** (파일 선택 창이 Windows 전용입니다)
- **Python 3.10 이상**
- **GPU 권장** — 없어도 동작하지만 매우 느립니다

### 2-2. 설치 순서

**① 소스 내려받기** — 모델 가중치가 Git LFS로 관리되므로 LFS를 먼저 설치합니다.

```bash
git lfs install
```

```bash
git clone https://github.com/Seongwon5/CrackTwinStudio.git
```

**② 필요한 패키지 설치**

```bash
pip install -r requirements.txt
```

**③ GPU를 사용한다면** CUDA 지원 torch를 별도로 설치합니다.

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

### 2-3. 설치 확인

아래 명령이 `True` 를 출력해야 정상입니다.

```bash
python -c "import trimesh.ray; print(trimesh.ray.has_embree)"
```

> ⚠️ **`False` 가 나오면 반드시 해결하고 진행하세요.** 이 상태로 분석하면 오류 없이
> **아무 균열도 없는 빈 보고서**가 만들어집니다. → [문제 해결](#embreex-없음--가장-흔한-사고)

모델 파일 크기도 확인합니다. `model/best.pt` 가 **약 118MB** 여야 합니다.
134바이트라면 LFS 파일을 받지 못한 것입니다.

```bash
git lfs pull
```

### 2-4. 실행

```bash
python app.py
```

대시보드 창이 열리면 준비 완료입니다.

## 3. 입력 데이터 준비

분석에는 **두 가지**가 필요합니다.

### 3-1. 이미지 + XMP 폴더

포토그래메트리 소프트웨어(3DF Zephyr 등)에서 내보낸 **사진과 카메라 파라미터 파일(XMP)** 을
같은 폴더에 둡니다.

```
격납건물_1층/
├── IMG_0001.JPG
├── IMG_0001.JPG.xmp     ← 또는 IMG_0001.xmp
├── IMG_0002.JPG
├── IMG_0002.JPG.xmp
└── ...
```

- 파일명 규칙은 `사진.jpg.xmp` 와 `사진.xmp` **둘 다** 인식합니다
- 지원 이미지: `.jpg .jpeg .png .bmp .tif .tiff`

> **XMP가 없는 사진은 분석에서 제외됩니다.** 카메라 위치를 모르면 3D에 얹을 수 없기 때문입니다.
> 제외된 사진은 분석 로그와 보고서에 목록으로 표시되니 꼭 확인하세요.

### 3-2. PLY 메시

같은 촬영에서 만든 **3D 모델 파일(.ply)** 입니다.

> ⚠️ **가장 중요한 조건: 1 unit = 1 m**
>
> PLY 좌표가 **미터 단위로 정규화**되어 있어야 합니다. 이 전제가 깨지면
> 폭·길이 mm 값이 전부 틀립니다. 포토그래메트리 단계에서 실측 기준으로
> 스케일을 맞춰 두세요.

또한 PLY는 **삼각형 메시**여야 합니다. 점만 있는 포인트클라우드는 오류가 납니다.

## 4. 보고서 만들기

대시보드 **1번 카드**에서 진행합니다.

| 순서 | 할 일 |
|---|---|
| ① | **이미지+XMP 폴더** 버튼 → 사진이 든 폴더 선택 |
| ② | **PLY 메시** 버튼 → 3D 모델 파일 선택 |
| ③ | **보고서 이름** 입력 (비우면 폴더명 사용) |
| ④ | **크랙 검출 수행** 체크 확인 (해제하면 카메라 위치만 담긴 보고서) |
| ⑤ | **분석 시작** |

진행률과 로그가 실시간으로 표시됩니다. 완료되면 `reports/` 폴더에 `.twin` 파일이 생기고
아래 목록에 나타납니다.

### 소요 시간 감각

GPU 기준 **사진 1장당 수 초**입니다. 1,000장이면 1~2시간 정도를 예상하세요.
같은 사진을 다시 분석할 때는 AI 추론 결과가 캐시되어 훨씬 빠릅니다.

### 분석 로그에서 꼭 볼 것

```
⚠ XMP(카메라 파라미터) 없어 제외: 694장 [...]     ← 의도한 게 맞는지 확인
이미지 1288장 발견 · 분석 대상 594장
  병합 결과: 핫스팟 53000개(뷰별 인스턴스) → 4210개 크랙
```

"발견"과 "분석 대상" 숫자가 크게 다르면 XMP 파일이 빠진 것입니다.

## 5. 뷰어 사용법

대시보드 **2번 카드**에서 보고서를 **열기** 하면 새 창이 뜹니다. 여러 보고서를 동시에 열 수 있습니다.

### 5-1. 화면 구성

```
┌─────────────────────────────────────────────────────┐
│  상단: 심각도 · 신뢰도 필터                           │
├──────────┬───────────────────────────┬──────────────┤
│ 좌측 도크 │                           │ 우측 패널     │
│ · 크랙목록│      3D 화면              │ · 이미지 목록 │
│ · 측정도구│                           │ · 카메라 정보 │
│ · 캘리브  │                           │              │
└──────────┴───────────────────────────┴──────────────┘
```

좌우 패널 경계를 드래그하면 폭을 조절할 수 있습니다.

### 5-2. 기본 조작

| 조작 | 동작 |
|---|---|
| **좌드래그** | 시점 회전 (둘러보기) |
| **마우스 휠** | 앞뒤 이동 (줌) |
| **우클릭 홀드** | 스코프 확대 — 멀리 있는 균열을 자세히 볼 때 |
| **짧은 클릭** | 선택 (균열 또는 카메라) |
| **우측 하단 기즈모** | 축 클릭 = 정면/상단/측면 뷰 |

### 5-3. 균열 확인하기

- **균열 위에 마우스를 올리면** 평균 폭·총 길이가 말풍선으로 뜨고 흰색으로 강조됩니다
- **균열을 클릭하면** 대표 사진이 확대되고 상세 수치가 표시됩니다
- 균열 색은 **심각도**를 나타냅니다 (아래 [측정값 읽는 법](#10-측정값-읽는-법) 참조)

**균열 튜브 굵기 — 실폭(×1)이 기본입니다.** 튜브 지름이 측정된 폭과 정확히 같습니다.
0.3mm 균열은 0.3mm 튜브라서 **가까이 가야 보입니다** — 그것이 실척의 의미입니다.
멀리서 균열 *분포*를 훑고 싶다면 상단 **표시** 메뉴에서 "실폭(×1) 굵기"를 끄세요 —
최소 4cm 두께로 과장되어 어디에 균열이 있는지 한눈에 보입니다.
(어느 모드든 마우스 호버·클릭은 굵기와 무관하게 넉넉한 영역으로 잡힙니다.)

### 5-4. 카메라(사진) 보기

3D 화면의 **파란 사각뿔**이 사진을 찍은 위치입니다.

- **클릭하면** 그 사진을 찍은 시점으로 카메라가 정확히 정렬됩니다
- 우측 이미지 목록에서 **좌클릭** = 그 시점으로 이동, **우클릭** = 원본 크게 보기
- 선택한 균열은 사진 위에 **노란 발광 선**으로 표시됩니다

### 5-5. 크랙 목록

좌측 **크랙 목록** 패널에서:

- 폭·길이·심각도 기준 **정렬**
- 항목 클릭 → 그 균열을 검출한 **가장 가까운 카메라 시점으로 이동**
- **CSV 내보내기** 로 전체 목록을 표 형식으로 저장

### 5-6. 필터

상단 바에서 두 가지를 조합(AND)해 걸러냅니다.

| 필터 | 값 |
|---|---|
| **심각도** | S1 경미 ~ S6 특이값 |
| **신뢰도** | 낮음 / 보통 / 높음 |

예: "심각도 S4 이상 + 신뢰도 높음"만 남기면 우선 보수 대상이 추려집니다.

### 5-7. 측정 도구

| 도구 | 용도 |
|---|---|
| **거리 측정** | 두 점 사이 거리 |
| **반경 측정** | 한 점 기준 반경 |
| **지점 검사 모드** | 표면의 임의 지점을 클릭 → 그 지점이 찍힌 사진들을 모아서 표시 |

### 5-8. 스케일 캘리브레이션 (중요)

실측 치수를 알고 있다면 이 기능으로 **모든 mm 값을 보정**할 수 있습니다.

1. 좌측 **기준 거리 지정** 클릭
2. 3D 화면에서 실제 길이를 아는 두 점을 클릭 (예: 기둥 폭, 타일 간격)
3. 실측값(mm) 입력 → **적용**

이후 모든 폭·길이·심각도가 보정된 값으로 재계산됩니다.

보정값은 보고서 옆 사이드카 파일(`<보고서>.twin.review.json`)에 저장됩니다.
**PDF 보고서에도 같은 보정이 적용**되며, 사이드카 파일을 `.twin`과 함께 옮기면
다른 PC에서도 유지됩니다. 좌측 **해제** 버튼으로 언제든 되돌릴 수 있습니다.

## 6. 균열 검토·승인

검사원이 AI 결과를 확인하고 수정하는 기능입니다. 균열을 클릭하면 상세 패널에 검토 항목이 나옵니다.

| 버튼 | 의미 |
|---|---|
| **확인** | AI 판정이 맞다 |
| **오탐** | 균열이 아니다 (얼룩·그림자 등) |
| **메모** | 자유 기록 |

검토 내용은 `.twin` 옆에 `<보고서이름>.twin.review.json` 파일로 저장됩니다.
원본 `.twin` 은 수정되지 않으므로 안전합니다.

> 이 검토 기록(특히 **오탐**)은 검출 AI 재학습 데이터로 쌓입니다 → [9장](#9-검토-라벨과-ai-재학습)

## 7. 검사 간 비교

같은 구조물을 **다른 시점에 두 번 촬영**했을 때, 균열의 신규 발생·성장을 추적합니다.

대시보드 **3번 카드**:

1. **이전 검사 (T1)** 와 **이번 검사 (T2)** 보고서를 각각 선택
2. **비교 실행**
3. 완료되면 비교 뷰어가 열립니다

### 결과 읽기

균열 색이 **변화 상태**를 나타냅니다.

| 색 | 상태 | 의미 |
|---|---|---|
| 🔴 빨강 | **신규** | 이번에 처음 발견 |
| 🟠 주황 | **성장** | 폭·길이가 유의미하게 커짐 |
| ⚫ 회색 | **불변** | 변화 없음 |
| 🟢 초록 | **감소?** | 작아짐 (측정 오차 가능성) |
| 🔵 파랑 | **미검출** | 이전엔 있었으나 이번에 안 잡힘 |

이전 검사의 균열은 **고스트(반투명)** 로 함께 표시됩니다.

3번째·4번째 검사도 이어서 붙일 수 있으며, 균열마다 **영속 ID**가 유지되어 이력이 누적됩니다.

> **판정 기준:** 촬영마다 좌표계가 다르므로 먼저 3D 정합을 수행하고,
> 뷰 간 측정 산포(노이즈 바닥)를 넘는 변화만 '성장'으로 판정합니다.
> 정합 품질이 기준에 못 미치면 **결과를 신뢰할 수 없어 중단**됩니다.
>
> **'미검출'은 보수 완료와 미관측을 구분하지 못합니다.** 현장 확인이 필요합니다.

## 8. PDF 보고서 내보내기

보고서 목록의 각 항목에서 **PDF** 버튼을 누릅니다.

구성:
1. **표지·요약** — 검사 개요, 균열 통계
2. **위치도** — 3D 모델 상 균열 분포
3. **균열 대장** — 번호·폭·길이·심각도·검토 상태 표
4. **사진 대지** — 주요 균열 사진

검토 기록이 있으면 대장에 함께 반영됩니다.

뷰어에서 적용한 [캘리브레이션](#5-8-스케일-캘리브레이션-중요)도 **모든 수치·심각도에
그대로 적용**되며, 표지에 보정 계수와 기준 실측값이 명시됩니다. 보정이 없으면
"무보정 값" 경고가 대신 표시됩니다.

## 9. 검토 라벨과 AI 재학습

예전의 "유형 분류 재학습" 기능은 **제거되었습니다.** 유형 분류기가 실제 균열을
얼룩으로 잘못 분류해 숨기는 위험이 커서, 오탐 문제는 **검출 AI 자체를 재학습**하는
방향으로 전환했기 때문입니다.

지금 하실 일은 하나입니다 — **뷰어에서 검토를 남기는 것.**

| 검토 | 재학습에서의 의미 |
|---|---|
| 오탐 (✗) | "이건 균열이 아니다" — 검출 모델이 다시는 속지 않도록 학습할 하드 네거티브 |
| 확인 (✓) | "이건 진짜 균열이다" — 양성 학습 데이터 |

검토는 보고서 옆 사이드카 파일(`<보고서>.twin.review.json`)에 자동으로 쌓이며,
검출 모델 재학습(파인튜닝) 기능이 준비되면 그대로 학습 데이터로 사용됩니다.

## 10. 측정값 읽는 법

### 10-1. 폭

한 균열에 대해 여러 폭 값이 표시됩니다.

| 표시 | 의미 | 언제 보나 |
|---|---|---|
| **중앙** | 폭 프로파일의 중앙값 | 균열의 일반적인 굵기 |
| **p95** | 상위 5% 지점 폭 | **심각도 판정 기준** |
| **최대** | 가장 넓은 지점 | 최악 지점 확인 |
| **3D폭** | 3D 표면에서 직접 실측 | 경사면 균열에서 더 정확 |

> p95를 심각도 기준으로 쓰는 이유: 최대값은 픽셀 하나의 노이즈에 흔들리고,
> 중앙값은 국소적인 확폭을 놓칩니다. 그 절충입니다.

**"≤0.4" 처럼 표시되는 폭 — 분해능 한계**

폭이 그 사진의 픽셀 크기(GSD)의 2배보다 작으면, 카메라가 실제 폭을 **분해하지 못한**
것입니다. 이때는 측정값 대신 **상한값**을 "≤" 와 함께 표시합니다.
"≤0.4mm"는 "0.4mm 이하인 것은 확실하지만 정확히 몇인지는 이 사진으로 알 수 없다"는 뜻입니다.
더 정확한 값이 필요하면 **더 가까이에서 다시 촬영**하세요.

**"±0.11" 처럼 붙는 값 — 측정 불확실도**

같은 균열을 3장 이상의 사진에서 검출한 경우, 사진마다 잰 폭의 산포(IQR/2)를
± 로 표시합니다. 이 값이 크면 촬영 각도·거리에 따라 측정이 흔들린다는 뜻이므로
그만큼 여유를 두고 판단하세요.

### 10-2. 길이

| 표시 | 의미 |
|---|---|
| **길이** | 최장 경로 — 균열의 대표 길이 |
| **총연장** | 가지를 포함한 전체 길이 |

가지가 많은 균열에서 두 값이 크게 차이납니다.

### 10-3. 심각도

폭(p95) 기준 **절대 등급**입니다.

| 등급 | 이름 | 폭 범위 |
|---|---|---|
| **S1** | 경미 | < 0.5mm |
| **S2** | 관찰 | 0.5 ~ 1mm |
| **S3** | 보통 | 1 ~ 3mm |
| **S4** | 심각 | 3 ~ 5mm |
| **S5** | 매우 심각 | 5 ~ 10mm |
| **S6** | **특이값** | > 10mm |

> **S6(특이값)이 많이 보이면 측정을 의심하세요.** 콘크리트 균열에서 10mm 초과는
> 비현실적입니다. 대부분 PLY 스케일이 잘못됐거나(1 unit ≠ 1m) 경사면 보정이 튄 경우입니다.

### 10-4. 신뢰도

AI가 그 지점을 균열이라고 판단한 확률입니다.

| 표시 | 확률 |
|---|---|
| 낮음 | < 0.7 |
| 보통 | 0.7 ~ 0.9 |
| 높음 | ≥ 0.9 |

### 10-5. ⚠️ 절대값 신뢰도에 대한 정직한 안내

**실측 치수로 검증하기 전까지 mm 절대값은 신뢰할 수 없습니다.**
모든 측정이 "PLY 1 unit = 1 m" 전제에 의존하기 때문입니다.

- ✅ **신뢰 가능**: 균열의 **상대적 순위**(어느 것이 더 심한가), **형상**, **위치**
- ⚠️ **검증 필요**: mm **절대값**

보고서에 최대 폭이 50mm를 넘는 균열이 있으면 자동으로 경고가 표시됩니다.
[캘리브레이션](#5-8-스케일-캘리브레이션-중요)으로 실측 보정을 권장합니다.

## 11. 문제 해결

### `embreex` 없음 — 가장 흔한 사고

**증상:** 분석은 끝나는데 균열이 하나도 없는 빈 보고서가 나옵니다.
로그에 이런 오류가 반복됩니다.

```
[오류] IMG_1553.JPG: Unable to allocate 575. MiB for an array with shape ...
```

**원인:** 3D 계산 가속 모듈이 없어 느린 방식으로 폴백하다가 메모리가 터집니다.
**조용히** 일어나므로 알아채기 어렵습니다.

**해결:**
```bash
pip install embreex
```

확인:
```bash
python -c "import trimesh.ray; print(trimesh.ray.has_embree)"
```

> `pyembree` 는 옛날 이름이라 지금은 소용없습니다. 반드시 `embreex` 입니다.

### 보고서가 열리지 않음

- **"구형식(v1) 보고서는 더 이상 지원하지 않습니다"** → 예전 버전에서 만든 파일입니다.
  원본 사진·PLY로 다시 분석해 주세요.
- **"보고서 파일 없음"** → 파일이 이동·삭제되었습니다.

### 균열이 너무 적게/많이 검출됨

- **너무 적다** → 이미지 해상도가 낮거나 균열이 얇습니다. 더 가까이 촬영하세요.
- **너무 많다** → 얼룩·그림자를 오검출 중일 수 있습니다.
  **신뢰도 필터**로 낮은 것부터 살펴보고, 오탐은 **검토(✗)**로 표시하세요 —
  PDF 대장에서 제외되고 [재학습 데이터](#9-검토-라벨과-ai-재학습)로 쌓입니다.

### 균열 위치가 사진과 어긋남 / 3D 위치가 엉뚱함

1. **세로로 찍은 사진(카메라를 돌려 촬영)이 섞여 있다면** 구버전에서 만든 보고서일 수
   있습니다. 구버전은 EXIF 회전 방향을 잘못 추측해 일부 사진이 180° 뒤집힌 채
   분석되는 문제가 있었습니다(수정됨). **재분석하면 해결됩니다.**
2. 그래도 어긋나면 XMP의 카메라 파라미터가 정확하지 않을 수 있습니다.
   포토그래메트리 단계의 정합 품질을 확인하세요.

### 폭 값이 비현실적으로 큼 (S6 특이값 다수)

1. PLY 스케일이 **1 unit = 1 m** 인지 확인
2. [캘리브레이션](#5-8-스케일-캘리브레이션-중요)으로 실측 보정

### 분석이 너무 느림

- GPU가 인식되는지 확인 — 로그 첫 줄에 `[cuda]` 가 나와야 합니다. `[cpu]` 면 CPU 모드입니다
- CUDA 지원 torch가 설치되었는지 확인하세요

### 3D 화면이 버벅임

메시가 매우 크면(수천만 면) 렌더링이 무거워집니다.
포토그래메트리 단계에서 메시를 단순화(데시메이션)해 다시 만드는 것을 권장합니다.

### 디스크 공간 부족

- `cache/` — AI 추론 캐시입니다. **지워도 안전**하며 다음 분석이 조금 느려질 뿐입니다
- `reports/*.twin` — 실제 보고서입니다. 지우면 복구되지 않습니다
