## [Unreleased]

### 수정
- **긴 크랙의 대표 뷰 실패 수정** — 대표 뷰 선택이 크랙 중심점 하나의 가시성만
  검사해서, 여러 뷰에 걸친 긴 크랙은 중심점이 어느 멤버 뷰 화면에도 안 들어가
  엉뚱한 중앙 크롭으로 떨어졌다. 중심선 커버리지(가장 많이 보는 뷰) 기준으로
  교체하고, 크롭도 그 뷰에 보이는 구간의 중앙에 맞춘다. 부분만 보이면
  "크랙의 N% 구간" 을 라벨에 표기.
- **세로 촬영 이미지 180° 뒤집힘 수정** — 이미지 방향을 종횡비로 추측하던 로직이
  90° 시계/반시계를 구분하지 못해(회전 후 모양이 동일), EXIF ori=8 사진이 보정
  기준으로 180° 뒤집힌 채 분석되던 문제(실측: interior 데이터셋 391장 중 172장 —
  전 검출이 엉뚱한 3D 위치로 역투영됨). `load_oriented()` 가 치수 근거로 판정하도록
  교체: calib==원시 치수면 원시 그대로(Zephyr 는 EXIF 를 무시하고 보정),
  calib==EXIF 적용 치수면 태그 그대로 적용(방향 모호성 없음).
  ⚠ 세로 사진이 섞인 기존 보고서는 재분석해야 한다.
- **추론 캐시의 방향 오염 차단** — 캐시 키에 방향 판정 태그를 추가. 같은 파일·같은
  치수라도 방향 로직이 바뀌면 픽셀 배치가 180° 다른데 키가 같아서, 위 수정 직후
  구 방향에서 만든 확률맵이 그대로 히트해 마스크가 어긋나는 것을 검증 중 발견.
  구 캐시는 키가 달라져 자동 무효화된다(재추론).

### 제거
- **크랙 유형 분류 폐지** — 분류기(cracktype.py·crack_type.json), 유형 재학습 루프
  (retrain_type.py·대시보드 카드·/api/retrain*), 뷰어 유형 필터·유형수정 UI,
  PDF 유형 열을 전부 제거. 라벨 205개짜리 예비 분류기가 실제 균열을 blob 으로
  오분류해 필터에 숨기는 위험(결함 놓침)이 오탐 정리 효과보다 컸다.
  오탐 억제는 검토(확인/오탐) + **검출 모델 자체의 재학습**으로 방향 전환 —
  사이드카의 오탐 라벨이 하드 네거티브 학습 데이터로 쌓인다.
  구 .twin 의 type 필드는 무시된다(하위 호환). project_to_cam 은 범용 기하라
  pipeline.py 로 이관. 뷰어의 유형별 병합 버퍼도 단일 버퍼로 단순화.

### 변경
- **폭 측정 1차 소스를 3D 엣지 쌍 실측으로 승격** — 기존 스케일맵(z/fx×1/cosθ) 곱은
  광선 오착지 시 조용히 폭주했고(실측: 픽셀폭 2px 균열이 444mm 로 보고) 등방 cosθ
  근사였다. 좌·우 경계 역투영 |L3d−R3d| 를 깊이 일치 게이트 2종(좌우 착지 깊이차 ·
  쌍 깊이 vs 중심선 중앙 깊이)으로 걸러 1차 소스로 쓴다 — 오착지가 '조용한 25cm'가
  아니라 '명시적 측정 실패'가 된다. 유효 표본 부족 시 스케일맵 폴백(width_src="2d",
  국소 스케일 3×중앙 초과점은 무효화). 두 방식이 1.3× 이상 다르면 width_flag.
  검증(interior 오염 이미지 11장): 444mm 균열 → 중앙 10mm 로 정상화, 남은 대형
  max 는 게이트 통과한 '실제로 넓은 어두운 영역'(blob 오탐)으로 유형 분류가 담당.
  전 규모 검증(interior 391장, 구 알고리즘 보고서와 동일 조건 대조):
  3D 소스 채택 1,826/1,828(99.9%) · p95폭 중앙 4.55→3.62mm(−20%) ·
  max>100mm 33→22개(−33%) · **심각도 S6(특이값) 341→243(−29%)** — 분포 전체가
  아래로 이동(cosθ 과보정·오착지 인플레이션 제거). p95폭 상위는 전부 joint/blob
  오탐으로 재편(crack형 >50mm 는 926개 중 3개), 검출·병합·정합 진단은 완전 동일
  (결정성 재확인). 잔여: 방식 불일치 플래그 37% — 임계(1.3×) 조정 후보.

### 추가
- **뷰 간 정합 오차 자기진단** — 병합 단계에서 같은 균열의 뷰별 중심선이 3D 에서
  어긋난 거리(중앙·p90 mm)를 실측해 `report_meta` 에 기록하고 뷰어 요약에 표시.
  병합 eps 의 3/4 를 넘으면 경고(⚠), 서로 3×eps 안까지 접근한 크랙 쌍은
  "조각남 의심"으로 집계 — "포토그래메트리가 부정확하면 측정이 무너지는가"에
  보고서마다 숫자로 답하는 장치. (폭·길이는 δz/z 비율 오차라 정합에 둔감하고,
  병합·신원이 임계값 기반이라 취약 — 그 취약 지점을 감시한다.)
- **크랙 튜브 실폭(×1) 표시** — 튜브 지름 = 측정 폭(기본값). 기존에는 최소 반경
  2cm + 2배 과장이라 0.3mm 균열이 4cm 튜브로 그려져(130배) 실제 폭을 오도했다.
  표시 메뉴의 토글로 강조(과장) 모드와 전환 가능(localStorage 기억).
  실폭 모드는 표면 위 6cm 띄우던 오프셋도 반경에 비례하도록 줄여 표면에 얹힌 듯
  보인다. 호버·클릭은 화면 14px 히트박스라 굵기와 무관하게 동작.
- **측정 바닥(분해능 한계) 표기** — 파이프라인이 균열마다 대표 뷰의 GSD(`gsd_mm`)를
  기록하고, 폭이 2×GSD 미만이면 뷰어·PDF 가 "≤상한" 으로 검열 표기한다.
  분해능 밖에서 잰 값을 정밀한 실측처럼 보이게 하던 가짜 정밀도를 제거.
- **뷰 간 산포 불확실도(±)** — 같은 균열을 3장 이상에서 검출하면 뷰별 폭의
  IQR/2 를 `w_unc_mm` 로 저장하고 뷰어·PDF 대장(± 열)에 표기.
- **캘리브레이션 영속화** — 뷰어 2점 캘리브레이션을 사이드카
  (`<twin>.review.json` 의 `calib`)에 저장(`POST /api/calib`). PDF 가 같은 보정을
  모든 수치·심각도에 적용하고 표지에 계수를 명시. 구버전 localStorage 값은
  부팅 시 1회 자동 마이그레이션.

## 2026-07-24 — 심각도 체계 정리

### 변경
- **심각도를 '상대 순위' → '절대 폭 기준'으로 교체.** 기존 방식(길이×폭 상대 순위)은
  보고서 간 비교가 불가능했다. 폭 기준 로그 5등급(G1~G5) 도입
- **심각도·신뢰도 기준 통일(6구간).** 화면에 기준이 둘(심각도 + 판정등급 A~D)이라 혼란스러웠던 문제 해결.
  경계 0.5/1/3/5/10mm, `S6`(10mm 초과)는 '특이값'으로 분리해 측정 오류를 눈에 띄게 함

### 제거
- **유형 '실금(craze)' 폐지** — 실금도 결국 가는 균열이라 '크랙'으로 흡수(4→3 클래스).
  구 보고서의 `craze` 는 읽는 쪽에서 `crack` 으로 폴백

- **하이라이트 역투영 신뢰성** — 멤버 뷰 한정 + 검출 마스크 스냅
- **하이라이트 모양 붕괴(사각형 아티팩트)** — 정점 스냅 → 강체 이동 정렬
- **캐시 히트 시 OOM** — 후처리 대기열 배압 추가.
  추론이 0초가 되면 메인 루프가 후처리를 앞질러 `prob`(~80MB/장)가 무한히 쌓이던 문제
- 대표 이미지 크롭의 검은 여백 제거 — 위치 클램프
- 말풍선 위에서 시작하는 좌드래그 회전 허용
- 마스크 토글 해제 시 선택 균열 하이라이트도 함께 숨김

### 제거
- **'가상 대표곡선'(이방성 주곡선) 융합 방식 폐기** — 실제 균열 형상을 왜곡해
  라플라시안 스무딩으로 복구
